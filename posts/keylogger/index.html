Building a Cross-Platform Keylogger

pythonsecurity

This was built for an Ethical Hacking course at AUB. The assignment was to build a cross-platform keylogger that persists across reboots, encrypts its logs, exfiltrates data via email, and evades Windows Defender. The goal wasn't to build and distribute malware, but to understand how these attacks work and how to defend against them.

How it works

The keylogger has four components, each mirroring a technique used by real-world keyloggers.

Keystroke capture

The tool uses pynput to hook into keyboard events. Every key press is captured silently in the background with no visible window or terminal. This isn't what makes it a keylogger though, it's just one of the components of one.

Encrypted logging

Each keystroke is encrypted before being written to a file in the system's temp directory. If a defender finds the log file, they can't read it without the key.

Persistence

A keylogger that dies on reboot is useless. The tool handles persistence differently on each platform:

On Linux, it adds a @reboot entry to the user's crontab. On Windows, it writes a registry key under HKCU\Software\Microsoft\Windows\CurrentVersion\Run, disguised as "SystemUpdater" to look like a legitimate process.

Data exfiltration

A background thread runs on a 2-minute interval. It reads the encrypted log file, decrypts the contents, and sends them to a Gmail address over SMTP with TLS. The email arrives with the subject "Keystroke Log."

Antivirus evasion

I tested the packaged executable against two antivirus solutions on an up-to-date Windows 10 machine (April 2025).

Microsoft Defender didn't flag it. Running a direct scan on the file returned no threats, and the keylogger ran in the background without being detected.

Kaspersky also didn't flag it when running a direct scan. It probably did not match any of the known signatures so it wasn't detected as a threat. But once the keylogger actually ran, Kaspersky's behavior blocker detected its activity and killed the process.

This is the difference between signature-based and behavior-based detection. Defender only checked the file against known signatures and found nothing. Kaspersky monitored what the process was doing at runtime, like hooking keyboard input, writing encrypted files, sending emails and flagged it as malicious based on behavior.

How to detect this

Even without antivirus, manual inspection can catch most of these techniques.

On Unix-like systems, check your crontab with crontab -l and look for @reboot entries pointing to executables in unusual paths. On Windows, inspect the registry at HKCU\Software\Microsoft\Windows\CurrentVersion\Run for entries you don't recognize. A tool like Autoruns makes this easier.

A process sending emails via port 465 from a non-email application is a red flag. On Unix-like systems, ps aux will show suspicious background processes. On Windows, Process Explorer gives more detail than Task Manager.

The log file is written to the system temp directory. Files in /tmp/ or %TEMP% that keep growing are worth inspecting, even if encrypted.

What I learned

The main takeaway was how simple it is to build something like this. The actual keylogging is a few lines of pynput code, persistence is a crontab entry or a registry key and exfiltration is simple. None of these are advanced techniques individually and tools like this can easily be built, so it's important to learn malware detection techniques.

The antivirus test was interesting. It showed that signature-based detection isn't enough. A simple custom written Python script with no known signatures can bypass Defender, but behavior-based detection catches it by analyzing its behavior. That's why endpoint protection focuses on behavior, not just signatures.
